# 사용 도구

이 시스템은 하나의 AI 도구에 모든 일을 맡기지 않고 역할을 나눕니다.

~~~mermaid
flowchart LR
    O["Owner"] <--> C["ChatGPT<br/>사고 · 설계 · 리뷰"]
    C --> U["ChatGPT<br/>구현·감사"]
    U --> G["GitHub / Tests / CI<br/>Durable Evidence"]
    G --> C
    C -. local reality 검증 .-> D["Desktop Commander<br/>개발 서버 감사"]
    U -. 완료 신호 .-> T["Telegram"]
~~~

탐색적 사고는 가볍게 유지하고, scope가 정리된 뒤 구현을 시작하며, evidence는 AI 대화 밖에 남기는 것이 핵심입니다.

## ChatGPT

요구사항, 브레인스토밍, 아키텍처, 설계, 문서, 테스트 전략과 다음 작업 결정뿐 아니라 기본 repository 구현, affected test, exact-HEAD 감사까지 담당합니다.

평소에는 가벼운 Chat 모드를 기본으로 사용하고, 장시간 autonomous work가 실제로 필요한 경우에만 Work 모드를 사용합니다.

## Cursor

선택적 호환 구현 도구입니다. 기본 구현 권한은 없습니다.

ChatGPT Chat이 승인된 개발 Linux 서버에서 직접 저장소를 수정하고 테스트·감사를 수행합니다. Cursor Desktop/CLI는 현재 Work Packet에 대해 owner가 명시적으로 요청하고 `IMPLEMENTER=CURSOR`가 기록된 경우에만 시작하거나 재개합니다. 그 외에는 Cursor session을 생성·resume·attach·wait하지 않습니다.

## agent persist

명시적으로 Cursor를 활성화한 Work Packet에서만 사용하는 Cursor-native persistent session입니다. SSH가 끊겨도 session이 남고, 소유자가 다시 붙어 진행을 볼 수 있습니다.

~~~bash
cd <target-worktree>
agent persist /work-resume
agent persist list
agent persist attach <session>
~~~

Cursor 호환 경로를 명시적으로 활성화한 경우에만 ChatGPT가 target worktree를 확인한 뒤 session을 시작합니다. `agent persist list`에 session이 실제로 보이는 경우에만 Cursor 전달 완료로 간주합니다.

`agent persist stop <session>`은 실행 중인 session을 중단하므로 의도적으로만 사용합니다. 사용자가 명시적으로 허용하지 않는 한 관찰할 수 없는 non-persistent `--print` 방식으로 대체하지 않습니다.

자세한 흐름은 [모바일 & 원격 작업](/ko/mobile-remote-workflow)을 참고합니다.

## Telegram

명시적으로 활성화한 장시간 Cursor 호환 작업에서는 Telegram으로 완료 메시지를 보낼 수 있습니다.

Telegram의 역할은 **알림**뿐입니다. 작업 상태나 검증 근거를 저장하는 곳으로 사용하지 않습니다. `COMPLETE`는 해당 작업이 최종 완료됐을 때만 보냅니다.

## GitHub

가장 중요한 durable engineering backbone입니다.

GitHub에는 코드, Git 이력, 제품 사양, ADR, 테스트, 회귀 기록, PR, 리뷰, CI, 현재 HEAD 기준 릴리스 검증 결과와 AI Work Packet을 남깁니다.

## Desktop Commander Remote MCP

[Desktop Commander Remote MCP](https://mcp.desktopcommander.app)를 ChatGPT와 연결하면 승인된 Linux 개발 서버의 파일과 터미널 상태를 직접 확인할 수 있습니다.

~~~mermaid
flowchart LR
    C["ChatGPT"] --> D["Desktop Commander"]
    D --> H["개발 Linux 서버"]
    H --> R["Repository / Worktree"]
    H --> P["Process / Test / Artifact"]
    G["GitHub"] --> C
    R --> C
    P --> C
~~~

GitHub만으로 확인할 수 없는 로컬 HEAD, 변경된 worktree, 실행 중인 테스트, 생성된 파일을 확인할 때 특히 유용합니다.

## Athena

Athena는 결정 이유, 설계 변경, cross-project history를 검색하기 위한 derived knowledge layer로 사용합니다.

현재 코드, 사양, 테스트와 릴리스 검증 결과의 기준은 계속 GitHub에 있습니다.
