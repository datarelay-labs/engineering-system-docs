# 도입 가이드

도입의 목표는 rule을 더 쌓는 것이 아니라 **중복 context를 줄이는 것**입니다.

## 사용자가 요청하는 방식

Engineering System 1.5.1에서도 사용자가 기억할 시작 방법은 동일하게 단순합니다.

~~~text
이 프로젝트에
https://github.com/datarelay-labs/engineering-system
을 적용해줘.
~~~

AI는 `standards/ADOPTION.md`를 따라 먼저 repository를 감사한 뒤 적용합니다.

~~~mermaid
flowchart LR
    A["Inventory"] --> B["Rule 분류"]
    B --> C["Test / CI / Release 탐색"]
    C --> D["CI Mode 결정"]
    D --> E["Deterministic Bootstrap"]
    E --> F["Adoption Qualification"]
~~~

## Deterministic Bootstrap

Read-only audit:

~~~bash
python tools/adopt.py --root /path/to/project --audit
~~~

Rule/CI 검토 후 적용:

~~~bash
python tools/adopt.py \
  --root /path/to/project \
  --apply \
  --ack-rule-review \
  --ci-mode shared \
  --test-command "<project-native test command>"
~~~

Bootstrap은 없는 공통 surface만 설치하고 기존 project file을 덮어쓰지 않습니다.

### Fail-closed 조건

다음은 AI가 추측하지 않고 중단합니다.

- dirty worktree
- 기존 AI/engineering rule 미검토
- test command 후보가 여러 개
- existing CI가 있는데 shared/native 책임이 결정되지 않음
- 기존 adoption을 destructive overwrite해야 함
- immutable canonical baseline SHA를 확인할 수 없음

## Managed Adoption Identity

1.5.1 adopted repository는 어떤 canonical standard와 어떤 project-native gate가 실제 책임을 가지는지 증명할 수 있도록 다음 identity를 기록합니다.

~~~yaml
engineering_system:
  version: "1.5.1"
  mode: adopted
  baseline: "<40-character canonical commit SHA>"
  ci_mode: native
  native_ci_workflows:
    - ".github/workflows/project-ci.yml"
  merge_gate_status: verified

operations:
  production_oriented: true
  runbook_required: true
  incident_response_required: true
~~~

`ci_mode`는 `shared` 또는 `native`입니다.

- **shared**: Engineering System reusable affected-test workflow 사용
- **native**: 기존 project CI를 유지하고 affected-test invariant를 담당하는 실제 workflow file을 명시하며 generated Engineering System workflow는 compliance만 수행
- `merge_gate_status`: `verified`, `advisory`, `unknown` 중 하나이며 workflow가 존재한다는 이유만으로 branch protection을 추측하지 않음
- Production-oriented repository는 runbook과 incident-response posture를 명시적으로 기록

Engineering System 1.5는 material design-bearing change를 가벼운 `standards/DESIGN.md` gate로, production-impacting failure를 `standards/OPERATIONS.md` incident lifecycle로 routing합니다. 매 작업마다 새 설계 문서나 incident 문서를 만들라는 의미가 아니라, 결정에 맞는 가장 작은 durable artifact를 사용합니다.

## 새 Repository

Canonical template은 다음 repository에서 가져옵니다.

[github.com/datarelay-labs/engineering-system](https://github.com/datarelay-labs/engineering-system)

기본 adoption에 필요한 것은 다음 네 가지입니다.

~~~text
AGENTS.md
.engineering/project.yaml
.engineering/tests.yaml
.engineering/release.yaml
~~~

Repository가 사용하는 Engineering System version을 pin합니다.

Cursor와 Session Continuity를 사용하는 경우에만 tool adapter와 continuity 파일을 추가합니다.

~~~text
.cursor/rules/engineering-system.mdc
.cursor/commands/resume.md
.github/ISSUE_TEMPLATE/ai-work-packet.md
~~~

Base engineering governance와 AI session continuity는 연결되어 있지만 동일한 기능은 아닙니다.

## 기존 Rules가 많은 Repository

새 always-on rule을 그냥 추가하지 않습니다.

먼저 기존 rule을 다음처럼 분류합니다.

~~~text
KEEP
KEEP_STRICTER
DUPLICATE
CONFLICT
OBSOLETE
UNKNOWN
~~~

제품 고유 architecture, routing, registry, security, persistence invariant는 유지합니다.

일반적인 engineering guidance가 중복되어 있다면 canonical Engineering System으로 수렴시켜 Cursor context를 줄입니다.

## Adoption이 아직 끝나지 않은 Repository

Work Packet은 존재하지만 Engineering System adoption이 별도 PR에서 진행 중일 수 있습니다.

Resume 시 `AGENTS.md` 또는 `.engineering/*`가 없다면:

- `ENGINEERING_SYSTEM_ADOPTION=ABSENT_OR_PENDING`으로 기록
- Work Packet이 유효하면 canonical Engineering System default 아래에서 계속 진행
- 현재 workstream이 adoption 자체를 승인하지 않았다면 adoption 파일을 임의로 생성·merge·수정하지 않음

이렇게 하면 release/feature 작업과 governance adoption이 섞이지 않습니다.

## Cursor User resume command 설치

Desktop에서 직접 resume이 필요할 때를 위해 Mac에 command를 둘 수 있습니다.

~~~bash
mkdir -p ~/.cursor/commands
curl -fsSL https://raw.githubusercontent.com/datarelay-labs/engineering-system/main/.cursor/commands/resume.md \
  -o ~/.cursor/commands/resume.md
~~~

개발 서버에서 ChatGPT가 Cursor CLI를 띄우는 **일반 원격 handoff**의 기본값은 `/work-resume`이며, 소유자가 평소에 `/resume`을 직접 칠 필요는 없습니다. 자세한 관찰·재접속 방법은 [모바일 & 원격 작업](/ko/mobile-remote-workflow)을 참고합니다.

## ChatGPT Custom Instructions는 짧게

Custom Instructions에는 전체 표준을 복사하지 않습니다.

다음 routing만 남깁니다.

- canonical Engineering System 사용
- repository 먼저 식별
- Cursor handoff와 chat continuity에 Work Packet 사용
- task-relevant context만 읽기
- 실행하지 않은 test나 다른 HEAD evidence를 PASS로 사용하지 않기

## 선택 사항: Desktop Commander

ChatGPT가 개발 서버를 직접 감사해야 한다면 Desktop Commander Remote MCP를 연결하고 allowed directory를 필요한 범위로 제한합니다.

## Adoption Qualification

파일이 존재한다는 이유만으로 PASS가 아닙니다.

Managed adoption은 required surface, version/baseline identity, session continuity, baseline-pinned workflow, test metadata, CI ownership, 설정된 release wiring을 검증합니다.

그 다음 실제 repository의 가장 싼 project-native smoke/affected test를 실행해야 합니다.

최종적으로 다음을 deterministic하게 증명한 경우에만:

~~~text
ENGINEERING_SYSTEM_ADOPTION=PASS
~~~

라고 판단합니다.

## Session Continuity Smoke Test

~~~mermaid
flowchart LR
    A["ChatGPT<br/>Cursor에 넘겨줘"] --> B["AI Work Packet"]
    B --> C["ChatGPT가 Cursor CLI 시작<br/>/work-resume"]
    C --> B
    B --> D["ChatGPT<br/>Cursor 끝났어. 계속"]
~~~

긴 prompt를 복사하지 않고 같은 workstream이 이어지면 continuity path가 정상 동작하는 것입니다. 소유자가 평소에 `/resume`이나 `/work-resume`을 직접 칠 필요는 없습니다.
