# 모바일 & 원격 작업

작업 장소가 바뀌어도 engineering workflow가 끊기지 않도록 구성했습니다.

책상에서는 Mac의 Cursor Desktop을 사용할 수 있습니다.

이동 중에는 개발 Linux 서버에서 Cursor CLI가 실행되고, 소유자는 휴대폰 SSH로 같은 서버에 접속해 진행 상황을 확인합니다.

## 다 잊었을 때 — 이것만 하면 됩니다

1. [Engineering System 한국어 홈](https://engineering.datarelay.run/ko)을 엽니다.
2. **모바일 & 원격 작업** 페이지(이 문서)로 옵니다.
3. 일반 개발 handoff는 ChatGPT에 이것만 말합니다: **「Cursor에 넘겨줘」**
4. 실행 중인 Cursor를 보려면:
   1. 개발 서버에 SSH
   2. `agent persist list`
   3. `agent persist attach <session>`
5. Telegram 완료 알림을 받으면 ChatGPT에 **「Cursor 끝났어. 계속」**이라고 말합니다.

정확한 서버 hostname과 project worktree는 프로젝트마다 다릅니다. 이 handbook에 Data Relay Control 같은 특정 경로를 하드코딩하지 않습니다.

## 「Cursor에 넘겨줘」는 ChatGPT가 end-to-end로 넘긴다는 뜻

소유자가 다음처럼 말하면:

- **「Cursor에 넘겨줘」**
- **「Cursor가 작업하게 해줘」**
- Cursor에 구현을 넘기라는 동등한 지시

기본 workflow는 다음과 같습니다.

1. ChatGPT가 실제 GitHub/repository 상태를 확인합니다.
2. ChatGPT가 repository-scoped `[AI Work]` Work Packet을 만들거나 갱신합니다.
3. ChatGPT가 올바른 격리 worktree와 branch를 식별·준비합니다.
4. ChatGPT가 현재 `/work-resume` command/rules를 확인·설치합니다.
5. ChatGPT가 승인된 개발 서버에서 Cursor CLI를 직접 시작합니다.
6. Cursor는 `/work-resume`을 받아 bounded implementation을 수행합니다.
7. Cursor는 validation, PR, CI/review, merge, linked issue 종료, Work Packet terminal completion까지 기계적으로 가능한 범위를 계속합니다.
8. Telegram COMPLETE는 workstream이 terminal 완료될 때만 보냅니다.
9. 소유자가 **「Cursor 끝났어. 계속」**이라고 말하면 ChatGPT는 텍스트 PASS를 믿지 않고 GitHub/CI/PR/issue/worktree 상태를 독립적으로 재검증합니다.

소유자가 평소에 Cursor CLI를 직접 시작할 필요는 없습니다.

예외: browser login, account, credential, approval처럼 원격으로 끝낼 수 없는 단계는 여전히 소유자 개입이 필요합니다.

## 전체 오케스트레이션

~~~mermaid
flowchart LR
    O["Owner<br/>Cursor에 넘겨줘"] --> C["ChatGPT<br/>오케스트레이션"]
    C --> W["Work Packet<br/>+ worktree/branch"]
    W --> P["Cursor persistent session<br/>/work-resume"]
    P --> G["PR · CI · merge"]
    G --> T["Telegram<br/>COMPLETE"]
    T --> O2["Owner<br/>Cursor 끝났어. 계속"]
    O2 --> C2["ChatGPT<br/>독립 재검증"]
~~~

## ChatGPT가 시작한 Cursor 작업을 보는 방법

기본값은 **Cursor persistent session**입니다.

현재 설치된 Cursor CLI에서 확인한 관리 명령:

~~~text
agent persist list
agent persist attach <session>
agent persist stop <session>
~~~

정상 handoff는 확인된 target worktree에서 다음과 같이 시작합니다.

~~~bash
cd <target-worktree>
agent persist /work-resume
~~~

ChatGPT는 실행 전에 target repository/worktree를 확인하고, 실행 후 `agent persist list`에 새 session이 실제로 나타나는지 확인합니다. session이 보이기 전에는 Cursor 전달 완료로 간주하지 않습니다.

또한 `agent persist` 시작은 interactive Linux/macOS TTY가 필요합니다. 비대화형 원격 shell에서는 `Persistence requires an interactive Linux or macOS terminal.` 오류가 날 수 있으므로 ChatGPT가 원격 실행할 때는 필요한 TTY/pseudo-TTY를 준비합니다.

실무에서 소유자가 보는 흐름:

~~~bash
ssh <development-server>
agent persist list
agent persist attach <session>
~~~

의미:

- `persist list` — persistent session 목록을 보여 줍니다. session id와 바로 복사할 attach 명령이 함께 나옵니다.
- `persist attach` — 실행 중인 바로 그 Cursor session에 들어가 진행을 볼 수 있습니다.
- `persist stop` — 해당 실행 session을 끊는 **파괴적** 명령이므로 의도적으로만 사용합니다.

ChatGPT는 시작 후 persistent session 식별자와 바로 복사할 attach 명령을 소유자에게 알려 줘야 합니다.

사용자가 명시적으로 허용하지 않는 한 관찰할 수 없는 비-persistent `--print` 방식으로 자동 대체하지 않습니다.

## SSH로 직접 보지 않고 ChatGPT에게 진행 상황을 물어보기

실행 중인 Cursor를 직접 보고 싶을 때는 앞의 `agent persist attach <session>` 방법을 쓰면 됩니다. 하지만 **단순히 현재 상태, 진행률, 막힌 이유, 완료 예상 시간이 궁금한 경우에는 개발 서버에 직접 SSH할 필요가 없습니다.**

ChatGPT에 다음처럼 물어보면 됩니다.

~~~text
"Cursor 진행사항 확인해줘"
"Cursor 지금 뭐 하고 있어?"
"Full Suite 언제 끝날 것 같아?"
"Cursor 작업 끝났어. 계속"
~~~

개발 서버에 대한 원격 확인 권한이 있는 경우 ChatGPT는 사용자에게 터미널 출력을 복사해 달라고 요청하는 대신 실제 상태를 직접 확인합니다. 작업 성격에 따라 다음을 함께 점검합니다.

- target repository/worktree와 실행 중 persistent Cursor session (`agent persist list` 포함)
- Cursor process/session과 현재 실행 중인 child command 또는 test
- branch, exact HEAD, working tree clean/dirty, remote 동기화 상태
- Full Suite의 현재 test 위치, 전체 개수, 남은 test, long-running test
- `[AI Work]` Work Packet, PR, CI, linked issue 상태
- 완료된 작업이라면 Cursor의 텍스트 보고만 믿지 않고 GitHub와 실제 repository 상태를 독립 재검증

예를 들어 ChatGPT는 다음처럼 짧게 현재 상태를 알려줄 수 있습니다.

~~~text
CURSOR_SESSION=RUNNING
CURRENT_TEST=test_example.sh
FULL_SUITE=145/153
HEAD=<exact-sha>
WORKTREE=CLEAN
PUSH=NOT_YET
~~~

### 완료 예정 시간도 ChatGPT에게 물어볼 수 있습니다

"언제 끝날 것 같아?"라고 물으면 ChatGPT는 가능한 경우 다음 실제 증거를 이용해 남은 시간을 계산합니다.

- Full Suite 시작 시간과 현재까지 경과 시간
- 현재 test 순서 / 전체 scheduled test 수
- 남아 있는 long-running test와 각 timeout 상한
- 같은 test 경로의 이전 실행 시간이 있다면 그 기록

완료 시간은 **약속이 아니라 현재 상태에 기반한 추정치**입니다. 따라서 `약 10~20분 남음`처럼 범위로 알려주는 것이 원칙입니다. 실행 상태를 직접 확인할 수 없거나 시간 추정 근거가 부족하면 정확한 ETA를 만들어내지 않고 확인 불가 이유를 설명합니다.

정리하면 다음 두 방식 모두 지원합니다.

~~~text
원시 Cursor 화면을 직접 보고 싶다
  -> ssh <development-server>
  -> agent persist list
  -> agent persist attach <session>

상태·진행률·blocker·완료 예상 시간만 알고 싶다
  -> ChatGPT에 "Cursor 진행사항 확인해줘"
  -> ChatGPT가 개발 서버 + GitHub 상태를 직접 확인해 요약
~~~

## 두 가지 작업 모드

| 상황 | 주 인터페이스 | 실제 실행 환경 |
|---|---|---|
| 책상에서 장시간 작업 | Mac Cursor Desktop 또는 ChatGPT 오케스트레이션 | local 또는 remote project worktree |
| 이동 중 | 휴대폰 SSH + `agent persist` | 개발 Linux 서버의 Cursor CLI |

핵심은 **화면이 바뀌어도 실행 환경은 개발 서버에 계속 남아 있는 것**입니다.

## Telegram의 역할

Cursor workstream이 terminal 완료되면 Telegram으로 COMPLETE 메시지를 전송합니다.

~~~mermaid
flowchart LR
    A["ChatGPT가 Cursor 시작"] --> B["소유자는 터미널에서 떠남"]
    B --> C["장시간 구현 / 테스트 / PR·CI"]
    C --> D["Telegram COMPLETE"]
    D --> E["필요할 때만 복귀"]
~~~

terminal을 계속 보면서 끝났는지 확인할 필요는 없습니다.

Telegram은 알림 채널일 뿐 source of truth가 아닙니다.

## 현재 남아 있는 수동 구간

~~~text
Cursor workstream terminal 완료
  -> Telegram COMPLETE
  -> 소유자: 「Cursor 끝났어. 계속」
  -> ChatGPT가 GitHub/CI/PR/issue/worktree를 독립 재검증
  -> 다음 작업 결정
~~~

이 수동 구간이 있어도 실제 authority는 copied output이 아니라 repository state, test, CI, runtime evidence입니다.

browser/account/login/credential/approval처럼 원격으로 끝낼 수 없는 단계만 소유자 개입이 필요합니다.

필요하면 ChatGPT가 Desktop Commander로 개발 서버를 직접 확인할 수 있습니다.
