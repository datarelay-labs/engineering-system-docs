# Data Relay Engineering System

**ChatGPT Chat이 기본 구현자이자 조정자입니다. GitHub는 durable state를 보관하고, 개발 서버 직접 감사는 실제 상태를 검증합니다. Cursor는 기본 비활성화된 선택 호환 경로입니다.**

이 시스템은 AI 개발 자체보다 그 주변에서 반복되던 불편을 줄이기 위해 만들어졌습니다.

긴 Cursor 프롬프트, 대화창 사이의 작업 전달, 오래된 로드맵, 사라지는 설계 이유, 불필요한 전체 테스트, 이동 중 터미널 확인 같은 문제를 하나씩 줄이면서 현재 구조가 만들어졌습니다.

## 한눈에 보는 전체 구조

~~~mermaid
flowchart LR
    U["사용자"] <--> C["ChatGPT<br/>설계·구현·테스트·감사"]
    C --> W["GitHub AI Work Packet<br/>권한·현재 상태"]
    W --> G["GitHub<br/>Code·Spec·Test·PR·CI"]
    G --> C
    C <--> D["Desktop Commander<br/>개발 서버 직접 감사"]
    G --> A["Athena<br/>결정·히스토리 검색"]
    W -. explicit IMPLEMENTER=CURSOR .-> R["선택적 Cursor<br/>/work-resume"]
    R --> G
~~~

<Note>
  기준이 되는 기록은 GitHub에 남깁니다. Athena, 이 설명서, Telegram, AI Work Packet은 각각 검색, 설명, 알림, 현재 작업 조정을 위한 보조 수단입니다.
</Note>

## 다 잊었을 때

1. 이 한국어 홈([engineering.datarelay.run/ko](https://engineering.datarelay.run/ko))을 엽니다.
2. [모바일 & 원격 작업](/ko/mobile-remote-workflow)으로 갑니다.
3. 일반 개발은 ChatGPT에 **「계속」**이라고 말합니다.
4. ChatGPT가 Work Packet과 실제 Git/GitHub 상태를 다시 읽고 직접 구현·테스트·감사를 이어갑니다.
5. Cursor가 꼭 필요할 때만 **「Cursor에 넘겨줘」**라고 명시적으로 요청합니다. 이 경우에만 `IMPLEMENTER=CURSOR`와 `/work-resume` 경로가 활성화됩니다.

## 시스템을 작게 유지하는 다섯 가지 원칙

1. 기준 기록은 GitHub에 두고, 설명서와 Athena는 이를 읽고 찾기 쉽게 만드는 용도로 사용합니다.
2. ChatGPT Chat이 기본 구현과 감사를 담당하고, Cursor는 Work Packet별 명시적 opt-in이 있을 때만 사용합니다.
3. 현재 작업에 필요한 정보만 읽습니다.
4. 비용이 큰 전체 검증 전에 변경 범위에 맞는 빠르고 재현 가능한 검사를 먼저 실행합니다.
5. 현재 작업 상태는 긴 전달 프롬프트가 아니라 해당 저장소의 Work Packet에 남깁니다.

## 핵심 원칙

이 시스템은 하나의 AI에게 모든 일을 맡기지 않습니다.

ChatGPT에서 요구사항과 설계를 정리한 뒤 같은 ChatGPT 컨텍스트에서 저장소 변경과 affected test를 수행하는 것이 기본입니다. Work Packet은 `IMPLEMENTER=CHATGPT_CHAT`으로 이 권한을 명시합니다.

Cursor는 사용자가 현재 Work Packet에서 명시적으로 요청하고 `IMPLEMENTER=CURSOR`가 기록된 경우에만 시작하거나 재개합니다. 어떤 경로를 쓰더라도 ChatGPT가 exact HEAD, 변경 상태, 테스트, PR/CI와 필요시 개발 서버 런타임을 검증합니다.

<Tip>
  하나만 기억하면 됩니다. **대화는 임시 작업 공간이고, 오래 남아야 할 개발 상태와 결정은 저장소에 남깁니다.**
</Tip>
