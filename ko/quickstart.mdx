# 빠른 시작

처음부터 모든 선택 도구를 설치할 필요는 없습니다.

먼저 durable state가 생기는 가장 작은 loop부터 구성합니다.

~~~mermaid
flowchart LR
    A["ChatGPT<br/>설계"] --> B["GitHub AI Work Packet"]
    B --> C["Cursor<br/>구현"]
    C --> D["Affected Tests"]
    D --> E["GitHub<br/>Commit / PR / CI"]
    E --> A
~~~

## 0. GitHub 접근부터 준비

Session Continuity는 ChatGPT와 Cursor가 repository-scoped GitHub Issue를 읽고 갱신할 수 있어야 합니다.

- ChatGPT는 Work Packet 생성·갱신을 위한 GitHub repository 접근이 필요합니다.
- Cursor `/work-resume`은 사용 가능한 GitHub integration 또는 인증된 `gh`가 필요합니다. 평소에는 ChatGPT가 Cursor CLI를 시작하고 `/work-resume`을 넘깁니다.
- 둘 다 없다면 과거 Handoff를 다시 복붙해서 복원하지 말고 GitHub 접근부터 구성합니다.

## 1. AI에게 Repository Adoption 요청

1.4부터 의도한 시작 방법은 단순합니다.

~~~text
이 프로젝트에
https://github.com/datarelay-labs/engineering-system
을 적용해줘.
~~~

AI는 template을 무작정 복사하는 것이 아니라 canonical adoption 절차를 따라야 합니다.

~~~text
Repository Inventory
  -> 기존 AI / Engineering Rule 분류
  -> Native Test / CI / Release Flow 탐색
  -> Project-specific / stricter invariant 보존
  -> Shared CI 또는 Native CI 명시적 선택
  -> 부족한 Engineering System surface bootstrap
  -> Adoption Qualification
~~~

Deterministic helper로 먼저 read-only audit을 할 수 있습니다.

~~~bash
python tools/adopt.py --root /path/to/project --audit
~~~

Managed 1.4 adoption은 Engineering System version과 immutable canonical baseline SHA를 함께 pin합니다.

## 2. Managed Adoption이 준비하는 것

Managed adoption은 다음 surface를 준비합니다.

~~~text
AGENTS.md
.engineering/project.yaml
.engineering/tests.yaml
.engineering/release.yaml
.cursor/rules/engineering-system.mdc
.cursor/commands/resume.md
.github/ISSUE_TEMPLATE/ai-work-packet.md
.github/workflows/engineering-system.yml
~~~

Project-native release qualification command가 명확하면 release preflight/gate wiring도 추가할 수 있습니다.

기존 project file은 기본적으로 덮어쓰지 않습니다. Dirty worktree, 미검토 AI rule, ambiguous test command, existing CI의 shared/native 결정 미완료, destructive upgrade는 fail-closed 처리합니다.

## 3. Session Continuity


ChatGPT ↔ Cursor resume workflow를 사용한다면 다음을 추가합니다.

~~~text
.cursor/commands/resume.md
.github/ISSUE_TEMPLATE/ai-work-packet.md
~~~

필요하면 repository Cursor rule도 canonical Engineering System을 참조하도록 둡니다.

## 4. ChatGPT Custom Instructions는 짧게

Custom Instructions에 Engineering System 전체를 복사하지 않습니다.

Global instruction은 routing만 담당하면 됩니다.

- target repository 먼저 식별
- canonical Engineering System 사용
- 현재 작업에 필요한 context만 로드
- handoff/resume은 repository Work Packet 사용
- 실행 전에 실제 Git/GitHub 상태 재검증
- 실행하지 않았거나 다른 HEAD의 evidence를 PASS로 사용하지 않기

## 5. 첫 Workflow 실행

~~~text
ChatGPT:
"Cursor에 넘겨줘"
  → ChatGPT가 Work Packet을 준비하고 Cursor CLI(/work-resume)를 시작

ChatGPT:
"Cursor 끝났어. 계속"
  → ChatGPT가 GitHub/CI/PR/issue/worktree를 독립 재검증
~~~

소유자가 평소에 `/resume`이나 `/work-resume`을 직접 칠 필요는 없습니다. 긴 prompt를 복사하지 않고 같은 workstream이 이어지면 continuity path가 정상입니다.

실행 중 Cursor를 보는 방법과 tmux fallback은 [모바일 & 원격 작업](/ko/mobile-remote-workflow)을 참고합니다.

## 구현 전에 확인할 것

Owner와 AI는 최소한 다음을 알아야 합니다.

~~~text
Change Type
Affected Domain
Public Contract
Persisted State
Security Boundary
Operational Impact
Required Tests
~~~

그 다음 가장 작은 올바른 변경을 하고, 오류를 가장 빨리 증명할 수 있는 deterministic check부터 실행합니다.

<Note>
  Product scope, 최종 의사결정, release 승인, human UX 판단은 Owner에게 남습니다. AI는 engineering process를 지원하며 scope를 임의로 넓히지 않습니다.
</Note>
