# Mobile and remote workflow

The development Linux server is the stable execution environment while the owner can move between Mac, phone, and other clients.

## If you forget everything

1. Open this handbook.
2. For a normal development handoff, tell ChatGPT: **"Cursor에 넘겨줘"**.
3. ChatGPT verifies GitHub state, updates the active `[AI Work]` Work Packet, prepares the branch/worktree, and starts Cursor CLI on the authorized development server.
4. To watch a running persistent Cursor task:

~~~bash
ssh <development-server>
agent persist list
agent persist attach <session>
~~~

5. If a task was intentionally launched under ordinary tmux:

~~~bash
tmux ls
tmux attach -t <session-name>
~~~

6. After terminal completion, tell ChatGPT: **"Cursor 끝났어. 계속"**. ChatGPT independently verifies GitHub/CI/PR/issue/worktree state.

## What "Cursor에 넘겨줘" means

The owner normally does not start Cursor CLI manually. ChatGPT handles the durable handoff end-to-end:

~~~mermaid
flowchart LR
    O["Owner<br/>Cursor에 넘겨줘"] --> C["ChatGPT<br/>verify + orchestrate"]
    C --> W["Work Packet<br/>branch/worktree"]
    W --> P["Cursor persistent session<br/>/work-resume"]
    P --> G["PR · CI · merge"]
    G --> T["Telegram COMPLETE"]
    T --> O2["Owner<br/>Cursor 끝났어. 계속"]
    O2 --> C2["ChatGPT<br/>independent verification"]
~~~

Browser login, account, credential, payment, or approval steps that cannot be completed remotely still require owner interaction.

## Cursor persistent sessions

Verified launch form for the installed CLI:

~~~bash
agent persist --force --trust --workspace <worktree> "<prompt>"
~~~

`persist` must come before `--force`, `--trust`, and `--workspace`. Putting the options before `persist` can bypass the persistence wrapper.

Launching a persistent session requires an interactive Linux/macOS TTY. A non-interactive shell can fail with:

~~~text
Persistence requires an interactive Linux or macOS terminal.
~~~

The owner normally only needs the management commands:

~~~bash
agent persist list
agent persist attach <session>
agent persist stop <session>
~~~

`stop` terminates the running session and should only be used intentionally. If an older task was launched with non-persistent `agent --print`, a new terminal cannot retroactively attach to that exact stream.

ChatGPT should report the persistent session name and a ready-to-copy attach command after starting it.

### Why ordinary `tmux ls` does not show Cursor persistent sessions

Cursor persistence uses a separate internal tmux server. The observed process form is:

~~~text
tmux -u -L cursor-agent ...
~~~

Therefore use `agent persist list` / `agent persist attach` for Cursor-native persistent sessions. Also avoid assuming that launching `agent persist` from inside an already-running ordinary tmux session creates another Cursor-managed persistent session; the installed CLI can detect `TMUX` and bypass the persistence wrapper.

## Ordinary tmux

Ordinary tmux is still useful for generic shell, test, server, or explicitly shared terminal sessions.

~~~bash
tmux ls
tmux attach -t <session-name>
~~~

Detach without stopping the task with:

~~~text
Ctrl-b, then d
~~~

`agent persist` and tmux overlap but solve different layers. Prefer `agent persist` for Cursor-native reconnectability; use ordinary tmux for general terminal persistence.

## Telegram

Telegram is a completion notification channel only. It is not engineering state or a source of truth. `COMPLETE` should be sent only after the workstream is terminally complete.

The authoritative state remains the repository, tests, CI, PR/issue state, and actual runtime evidence.
